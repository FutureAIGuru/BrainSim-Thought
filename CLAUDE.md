# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Build and test

```powershell
dotnet build "BrainSim Thought.sln"                     # UKS, BrainSim Thought (WPF app), Tests
dotnet test UKS.Tests/UKS.Tests.csproj                  # headless, net8.0, no WPF (NOT in the .sln)
dotnet test Tests/Tests.csproj                          # net8.0-windows, references the WPF app
dotnet test Tests/Tests.csproj --filter "FullyQualifiedName~ModuleInterpretTests"
dotnet test UKS.Tests/UKS.Tests.csproj --filter "FullyQualifiedName~ModuleInterpretTrialTests.Name"
```

- xUnit, test parallelization disabled per assembly (`AssemblyInfo.cs`); UKS uses process-wide statics (`ThoughtLabels`, `UKS.theUKS`), so keep it that way.
- `UKS.Tests` mostly `<Compile Include>`s selected files from `Tests/` and `BrainSimulator/` by link, plus small stubs (`ModuleAlgorithmContextStub.cs`, `ModuleBaseStub.cs`) that replace the WPF-dependent parts. To move a test into the headless suite, add a link there; any module source it needs must compile without WPF/`MainWindow` (hence `ModuleWord.Spelling.cs` is split from `ModuleWord.cs`). Its own file `ModuleInterpretTrialTests.cs` drives `ModuleInterpret.Input()` headlessly.
- If the WPF app is running, building the solution fails copying `BrainSim Thought.exe` (file lock). Don't redirect `Tests` output elsewhere (`-p:OutDir=...`) to get around it: many tests locate fixtures relative to the repo and then fail spuriously. The headless `UKS.Tests` is unaffected.
- The user may have the solution open in Visual Studio; avoid `git stash`/checkout of files they have open (VS can save its stale buffer back over the restored file).
- `artifacts/` is gitignored build/experiment output (many copies of `UKSContent`); ignore it when searching.
- `UKSWeb/` (ASP.NET, built by the `Dockerfile`) and `iOS/`, `BrainSimMAC/` depend only on `UKS/`.

## Architecture

- **`UKS/`** — the Universal Knowledge Store library (`UKS.UKS`, partial class across `UKS.*.cs`). Everything is a `Thought`; a `Link` is a Thought with `From`/`LinkType`/`To`; a `SeqElement` is a Thought in an ordered sequence (`NXT`, `FRST`, `VLU` value links — an element may carry several VLU "facets", selected by class via `GetElementValue(element, valueClass)`). Inheritance is `is-a` (`Parents`/`Children`, `HasAncestor`, `HasProperty`). Each `UKS` instance is independent, but implicit `string → Thought` conversion and static helpers use the ambient `UKS.UKS.theUKS` (see README). New stores: `new UKS(); store.CreateInitialStructure();` (`UKS.Initialize.cs` defines core types, `??` wildcard, `?`/`!`, sequence search options).
- **Dotted labels compose meaning** (`UKS.cs: GetOrAddThought`): `is.not.!` gets parents `is.not`, `!`; `??.noun` is a wildcard whose class is `noun`. `!` carries `setRelationship`, `?` carries `isPossible`. `UKS.ApplyTestOrSetAction(link)` (`UKS.Actions.cs`) strips those to the ordinary relationship type and either writes it (`.!`) or queries for matches (`.?`, wildcard operands search).
- **Text knowledge files** (`UKS.TextFile.cs`): one bracketed statement per line, `[from->type->to]`, nested `[a->means->[b->is.!->c]]`, sequences as `^a b c`, trailing number = weight, `#` comments. Loaded with `ImportTextFile` / `ProcessSingleLine`.
- **`BrainSimulator/`** — WPF host app. Modules (`Modules/Module*.cs` + `*Dlg.xaml`) derive from `ModuleBase` (WPF, `MainWindow`); `Initialize()`/`UKSInitializedNotification()` set up knowledge, the dialog calls module methods.

### ModuleInterpret — template-driven language understanding (experimental)

`BrainSimulator/Modules/Experimental/ModuleInterpret*.cs`, a partial class split by stage: `ModuleInterpret.cs` (fields, `Input`, `GetSequenceFromText`, inflected forms, `Execute`), `.Knowledge.cs` (`LoadLanguageKnowledge`, template definitions, saved-network migrations), `.Recognition.cs` (`GetTemplates`, `GetMeanings`, `Bind`), `.Generation.cs` (`GenerateSentence`), `.Reference.cs` (described noun phrases). `UKS.Tests` links all of them by wildcard. Proof of concept: all grammar lives in the UKS as data; the code only matches and substitutes.

- **Words vs. concepts**: words are `w:dog` Thoughts (under `word` via a `wordType` class such as `noun`, `adjective`, `copula`, `possessionVerb`, `numberWord`), spelled by a character sequence (`spelled`), linked by `means` to a grounded concept (`dog`, or an action type like `chases.ongoing.!`, `has.!`). Vocabulary and demo facts: `BrainSimulator/UKSContent/BasicWords.txt` (loaded from `AppContext.BaseDirectory/UKSContent` — the file must be copied to the output dir). Word lookup is `ModuleWord.FindWordsBySpelling` / `RememberSpelling`.
- **Inflected forms**: meanings belong only to base words, singular and present tense (for verbs the third-person form, `w:chases`, `w:is`, `w:has`). A form (`w:dogs`, `w:are`, `w:have`) is under `wordForm` with only a spelling, linked from its base by a link type under `hasInflection` that `marksInflection` an inflection (`[w:dog->hasPlural->w:dogs]`, `[hasPlural->marksInflection->plural]`). Verb agreement is the verb's plural; `hasPastTense` (→ `pastTense`) and `hasPresentParticiple` (→ `presentParticiple`) cover tenses (`w:chased`, `w:ate`, `w:chasing`, `w:eating`). An inflection that `addsMeaning` modifies the base meaning when read (`FilledThrough` → `WithInflection`, composing a dotted label: `chases.!` + past → `chases.past.!`); the plural adds none. A template element can require an inflection as an extra parent (`??.actionVerb.presentParticiple` in `verbPhrase1`); sequence search can't check that (wildcard parents are OR'ed), so `Admits` (GetTemplates) and `FilledThrough` do, and `ElementClasses` excludes inflections. Elements naming no inflection accept any. Every form is stored explicitly for now; spelling rules come later. In generation, a form counts as its base word's classes plus its inflection (so `precedesWord plural` admits `w:legs`, `presentParticiple followsWord copula` blocks "Dog chasing cat"); `WordsOf` offers base words before meaning-neutral forms, and `WordsExpressing` decomposes a modified concept (`chases.ongoing` = `chases` + what `presentParticiple` adds → `w:chasing`). `Admits` also rejects a word whose inflection adds meaning in an element that is not a `means` operand ("Fido was a dog": the classification templates' copula supplies nothing, so the past would be lost). Not yet in place: comparatives, possessives; `w:fed`/`ongoingVerb` are leftovers no template uses.
- **Shared sentence sequences**: `AddSequence` returns an existing identical sequence, and inflected input collapses to the same base words ("Is/Was Fido black?"), so `GetSequenceFromText` clears `inflectedAs`, `matchesTemplate`, `fills` and phrase VLU facets from a reused sequence before marking it.
- **Questions**: a template with `hasProperty asksQuestion` takes its relationship type from its words and `AsQuery` turns it into a query (`is.!` → `is.?`, `is.past.!` → `is.past.?`); such templates are skipped by generation. The copula means `is.!`, and `copulaAttributeTemplate`/`attributeQueryTemplate` take their type from it, so tense reaches the meaning. "What do dogs do?" asks `action.?`, matching any type under `action` (BasicWords classifies chases, eats). Locations follow the UKSWeb labs' convention: `location` is a class of places (yard, doghouse, kitchen, inside, outside) and the relationship type is `located` (`w:in` means `located.!`; `locativeAdverb` words like `w:outside` name the place; "Where is Fido?" asks `located.?`). Other prepositions mean dotted subtypes (`w:under` → `located.under.!`), so `located.?` finds them. `location` is `isExclusive` and `recordsHistory`, so a new location archives the old one (below).
- **Prepositional phrases**: `locativeTemplate` (copula + PP), `nounPhrase4` ("the cat in the kitchen": a described referent, see Reference), `eventLocationTemplate`/`eventLocationAdverbTemplate` (an action placed: nested MEANS `[[subj->verb->obj]->located.!->place]`, Lab 4's form), `whereEventQueryTemplate`. Nested patterns go through `BindPattern` (recognition), `Execute`/`Resolved` (a nested write is stated first, or looked up in a question) and `Unify` (generation). `IsMeansOperand` looks at any depth. Generation skips a phrase containing its own class (`ContainsItsClass`), else `nounPhrase4` recurses forever. In `FilledThrough`, nested phrases of one class resolve to the longest (`Follows` walks NXT, no counting).
- **Reading rules**: a sentence template (direct child of `template`) must start at the first word (`GetTemplates`) and end at the last (`Admits`); phrases can be anywhere. This settles PP attachment toward the reading that covers the sentence. In a question only the query meanings are executed; descriptive writes from its noun phrases are not.
- **History** (`UKS/UKS.History.cs`, moved unchanged from UKSWeb Lab 4): `AddStatementRecordingHistory` archives a displaced value (exclusive with the new one, and the type or target `recordsHistory`) as `was.TYPE` at the head of the source's `events` sequence (newest first, `validUntil` timestamps; repeat visits reuse the archived Relationship) and removes the conflicts. Called by `UKSWeb/StatementInputParser.Add` and by `ApplySetAction` (so every `.!` write). The desktop `ModuleUKSStatementDlg` "event" checkbox is a different thing: it logs the new statement itself into the same `events` sequence. `Execute` omits historical results from a present-tense question. Past tense in the interpreter is still `TYPE.past`, not the UKS's `was.TYPE`; reconciling them is deferred.
- **Templates**: Thoughts under `languagePattern` (`template` for wildcard patterns, `phrase` for fixed phrases like `p:is_a` in BasicWords). `hasWords` → a sequence of `??.class` wildcards and/or literal words; `means` → a wildcard (`??.noun`) or a Link pattern such as `[??.nounPhrase.subjectRole->is-a.!->??.nounPhrase.complementRole]`. All templates are text definitions in `LoadLanguageKnowledge()` (`quantityPossession0..9` in a loop over digits).
- **Roles, not positions** (a deliberate design constraint — no integer positions or counting in binding): a `means` operand refers to the template element whose value is the same Thought, so each wildcard/role may appear at most once per template. Where a class repeats, a role distinguishes the elements: `??.nounPhrase.subjectRole` has parents `??`, `nounPhrase`, `subjectRole`; roles (`subjectRole`, `complementRole` under `templateRole`) carry `isWildcard`, so only the class constrains fillers. A bare `??` operand that is not a template element is an open query variable. Don't name roles with plain English words or `object` (labels are case-insensitive and `Object` is a UKS root; typed words resolve to same-label concepts).
- **Pipeline** — `Input(sentence, rememberUnknownWords)` (the dialog passes `true`) returns a diagnostic text report. An input of several sentences (split on `.?!`) is interpreted one sentence at a time, each its own transaction; answers are joined. Per sentence:
  1. `GetSequenceFromText` — tokenize, lowercase, strip punctuation; resolve each spelling to a `w:` word; a stored inflected form is replaced by its base word and the sentence element gets `inflectedAs → plural` (no Pluralize.NET: the module must stay language-independent); unknown words throw `FormatException` unless remembered, in which case they get parent `unknownWordType`; ensure each word has a `means` concept; store as `SentenceIn*` (under `Sentence`) `hasWords` sequence.
  2. `GetTemplates` — repeatedly, from each start position, `FindSequencesByActivation(start, InterpretTemplateSearch, alternativeClass: languagePattern, matchClass: languagePattern)`; keep only the longest matches. Matches are recorded as `matchesTemplate` links on each covered word element, and the winner becomes a `languagePattern` VLU facet on those elements so larger templates can match `??.nounPhrase` etc. Unknown words filling a `??.class` slot are classified (`is-a` that class). Iterates to a fixpoint.
  3. `GetMeanings` — for each matched template run, walk the run and the template together (`FilledThrough`: a word's `means`, or the non-Link `means` of an already-resolved child phrase), recording `word -fills-> templateElement` links; then `Bind` each `means` operand by reference (role → template element → word that fills it → its meaning) and attach results as `means` links on the `matchesTemplate` link. Works from `matchesTemplate` attachments alone (a test builds them by hand). Iterates to a fixpoint.
  4. `Execute` — `ApplyTestOrSetAction` on each Link meaning: `.!` writes, `.?` queries ("Query results" section, then an "Answer" section).
- **Generation** — `GenerateSentence(Link fact)` runs a sentence template (direct child of `template`) in reverse: its `means` pattern unifies with the fact (element operands bind to the fact's Thoughts; fixed operands must express it, e.g. `is-a.!` expresses `is-a`), then its words are produced by walking the template. Bound elements → a word of the class whose `means` expresses the concept, or a phrase (child of the phrase class) whose own non-Link `means` is the bound element; unbound elements → a free choice of the class, never allowed for an element that appears in a `means` pattern. Each step lazily offers alternatives in preference order (base words before their inflected forms, then spelling order); the first word sequence satisfying the **word order constraints** wins. Those are BasicWords data, held by a word or inherited from its class: `precedesWord` (class of the next word that is not a modifier: `[adjective->hasProperty->isModifier]`, so `w:the` precedes the noun in "the black dog"), `precedesWordStartingWith` (class of next word's first letter, e.g. `w:an` → `vowel`), `followsWord` (previous word's class, e.g. `ongoingVerb` → `copula`). A phrase needing free choices is offered only when no phrase can express the concept without them (hence bare nouns via `nounPhrase3`, and "is an animal" rather than "is a the animal"). Only ordinary relationships are expressed (`.?`/`.!` types return null).
- **Articles and number in answers** — `GenerateSentence(fact, question)`: `NounsOf(question)` records each noun concept's article (or none) and plurality; `Express` then requires the same (hard) for those nouns, and for other nouns offers `nounPhrase2` with its article element bound to `a` first, then bare. The rest is BasicWords constraints: nouns are `countNoun`/`massNoun` (under `commonNoun`) or `properNoun`; `w:a`/`w:an` precede only a singular `countNoun`, `w:the` a `commonNoun`, `numberWord` a noun. `numberWord` is its own `wordType`, not an adjective (else "3 legs" reads as a described noun phrase and the quantity templates never match). `WordClasses` gives a base word the class `singular`. `AgreesInNumber` (in `FollowsWordOrder`): every word whose class has `agreesInNumber` (`verb`) is plural exactly when the sentence's first noun is, if it has a plural form and isn't a tense form. Without a question, answers default to singular with "a" ("A dog has a tail."). Learned nouns are plain `noun`, so they never get "a".
- **Transactions and undo** — `UKS/UKS.Journal.cs`: `BeginTransaction`/`EndTransaction`/`Undo` record structural changes (Links added/removed via `Thought.AddLink`, `UKS.WriteTheLink`, `Thought.RemoveLink`; Thoughts created when first labeled, in the `Label` setter) and reverse them newest first. Also recorded: relabels (`ThoughtRelabeled`, old label) and `Thought.Delete` of a non-Link (`ThoughtDeleted`; undo re-registers label and `AtomicThoughts`, then its removed Links come back). Weights, firing and TTL are not recorded. Transactions don't nest. One undo history per store: `ChangeUndoably(description, action)` / `RememberForUndo` push, `UndoLast` pops whichever source made the change — the Undo buttons in the Interpret, Add Statement and UKS dialogs (delete, delete child, delete link, rename) all share it; UKS-dialog Import is not undoable. `Input` runs as one transaction: undone unless the sentence is understood (`IsUnderstood`: one template with a meaning covers first word to last) and is a statement that executed something, so questions and misunderstood sentences leave the UKS unchanged and teach no words. Kept statements go on a stack for `UndoLastInput` (dialog: "Undo last statement").
- **Teaching** (`ModuleInterpret.Teaching.cs`) — a not-understood sentence sets `pendingSentence` and the reply asks to have it said another way. `Input` offers the next input to `TryToLearnFromExplanation` (not if it is the same words repunctuated: that's a correction, read as new): it is an explanation only if every sentence in it (split on `.?!`) is an understood statement and it shares a meaning with the pending sentence; otherwise it's undone and read normally. `Units` splits the pending sentence into recognized phrases and words with their meanings; `Align` maps each source/target Thought of the explanation's statements to exactly one unit (types map if a unit means them, else stay fixed); unmentioned units must be closed-class words (kept literal), else a specific "doesn't mention" reply. `DefineLearnedTemplate` writes text definitions (`learnedTemplate*`, roles `learnedRole*` under `templateRole`), one MEANS per statement plus `[[a]->conjoinedWith.!->[b]]` between consecutive statements (`conjoinedWith` isCommutative), marks it `isLearned` and `Capture`s it (Learning, below). The whole teaching exchange is one undoable transaction. Undo also clears `SequenceCache` entries for sequences it removes.
- **Learning** (`ModuleInterpret.Learning.cs`, deliberately domain-free so it can move into the UKS) — the user's model is match / capture / compete / consolidate / prune; prune is not implemented. A pattern's strength is the template Thought's own `Weight` (hand-written templates 1). `Capture`: weight 0.25, `isPlastic`. Compete: `CoveringMatches` orders whole-sentence readings by weight and `Covering` is the winner; `LosingMeanings` drops the rivals' meanings (unless the winner means the same) before `Execute`; equal-length phrase matches in `GetTemplates` are ordered by weight (`ByWeight`) for the phrase facet. Only the winner's outcome counts: losing costs nothing, and matching alone is not evidence. Success (a statement stored something, a question found an answer) → `Strengthen` (halfway to 1; past 0.8 `isPlastic` is cleared, but the weight can still change later) and each stated fact gets `statedBy` → the template (provenance, for later evidence-based forgetting). "(I'm still learning sentences like this one.)" while the winner was plastic. Fact weights are confidence only. Weight changes are not journaled, so Undo doesn't revert them. Lessons from `ModuleSequenceSegmenter` (why it isn't reused): an early false pattern could never be removed (consolidation was absolute and full recognition blocked rivals), learning needed repeated occurrences, and decay per miss made survival depend on input-suite size — so: capture on one presentation, never treat consolidation as permanent, and count failures only where the pattern was relevant. Two templates with identical words share one `hasWords` sequence and both match.
- **Misspellings** (`ModuleInterpret.Spelling.cs`) — in `GetSequenceFromText`, a spelling with no exact match goes to `CorrectedSpelling` before being learned: `ModuleWord.FindWordsCloseTo` runs the UKS `ApproximateSequenceSearch` (options `allowOutOfOrder`, `preferFirstLast`, `allowPartialMatch`; `UKS/UKS.SequenceApproximate.cs` `FindSequencesOutOfOrder`, dispatched from `FindSequencesByActivation`). Letters activate stored elements in any order, propagating up through compressed subsequences; confidence = activated share of the longer × (0.9 + 0.1 × in-order neighbor pairs) × 0.8 per wrong first/last letter. One candidate ≥ 0.85 is read silently with a note ("(I read "fdio" as "fido".)"); a best candidate ≥ 0.65 throws `UncertainSpellingException` → "Did you mean "the"?" with nothing learned; a lone `w:yes`/`w:no` (`replyWord`, meaning `affirmative`/`negative`) answers and rereads the sentence; anything else is new input. Answers are remembered for the session only (`acceptedCorrections`, `notMisspelled`).
- **Reference** (`ModuleInterpret.Reference.cs`) — a template that `hasProperty describesReferent` (`nounPhrase1` article adjective noun, `nounPhrase5` adjective noun, `nounPhrase4` with a PP) means the thing its description picks out, never facts about its class. `GetMeanings` (`DescribedReferent`) replaces its head and description meanings with one descriptor Link `[head->oneDescribedAs|kindDescribedAs->[head->is.!->black]]` (a nested phrase's descriptor can be the head); `FilledThrough` passes descriptors up like non-Link meanings. One vs kind is decided by the words: a first word that `isDefinite` (`w:the`, BasicWords) and a head with no plural filler → one; otherwise ("a black dog", "black dogs") a kind. Nothing is searched or made during recognition (losing readings leave no trace); `Execute`/`Resolved` call `Referent` for the winner. If the class itself satisfies the description (via `GetAttributes`), the class is the referent (nothing told apart). One: descendants that are not classes or `isAnonymousClass`, named or not (Fido) and satisfying it; several → `UnclearReferentException` ("I can't tell which dog you mean: fido or rover."); none → a new child `dog0` with `isInstance` and the description (a question gets no answer instead). Kind: an `isAnonymousClass` child with the description, found or made. Exception: an is-a write to a kind ("Rover is a small dog", `IsJoiningAKind`/`JoinKind`) makes no subclass: Rover is-a dog and is small (an agent like `ModuleClassCreate` may later make the class); this replaced `classificationAttributeTemplate`s (deleted from saved networks). An input that is only a describing phrase ("The hungry dog") introduces/finds its referent (`Introduced`). Generation (`ExpressReferent`) says a made referent (no word, `isInstance`/`isAnonymousClass`) with a describing phrase, article phrases first: "the" for an instance, "a" for a kind; the description is its first fact a phrase can say. Context that would settle which of several is meant is not considered.
- **Conjoined subjects** — `conjoinedClassificationTemplate`/`conjoinedAttributeTemplate` ("Fido and Rover are dogs."): `secondSubjectRole`, one MEANS per subject; `w:and` is a closed-class `conjunction`.
- **Report** — "Word attachments" lists each sentence word with its classes, properties and inflection, then its templates: `w:is (copula, pastTense)    attributeQueryTemplate`.
- **Dialog** — Enter in the input runs `Input`; the Answer box shows `ModuleInterpret.Answer` (query answer, "I don't know.", "OK.", "I don't understand.", or the unknown-words message) and Details shows the diagnostic report.
- Queries go through `GetAttributes` (`ApplyTestAction`), so they inherit and see rules whose conditions are met. A yes/no query (no wildcard) needs exactly the type asked (`is.past` doesn't answer `is`); `is-a` isn't among attributes, so it uses the stored link.
- `InterpretLanguage.txt` is an older `interpret:`/`slot:` dialect and is **not loaded** (import commented out). `InterpretTrials.txt` lists the demo sentences and expected relationships; they are automated in `UKS.Tests` (`ModuleInterpretTrialTests`) and `Tests/ModuleInterpretTests.cs`.
- Output strings use `→` (e.g. `[fido→is-a.!→dog]`); tests assert on these.
