# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Build and test

```powershell
dotnet build "BrainSim Thought.sln"                     # UKS, BrainSim Thought (WPF app), Tests
dotnet test UKS.Tests/UKS.Tests.csproj                  # headless, net10.0, no WPF (NOT in the .sln)
dotnet test Tests/Tests.csproj                          # net10.0-windows, references the WPF app
dotnet test Tests/Tests.csproj --filter "FullyQualifiedName~ModuleInterpretTests"
dotnet test UKS.Tests/UKS.Tests.csproj --filter "FullyQualifiedName~ModuleInterpretTrialTests.Name"
```

- xUnit, test parallelization disabled per assembly (`AssemblyInfo.cs`); some modules share statics (e.g. `MainWindow.theUKS`), so keep it that way.
- `UKS.Tests` mostly `<Compile Include>`s selected files from `Tests/` and `BrainSimulator/` by link, plus small stubs (`ModuleAlgorithmContextStub.cs`, `ModuleBaseStub.cs`) that replace the WPF-dependent parts. To move a test into the headless suite, add a link there; any module source it needs must compile without WPF/`MainWindow` (hence `ModuleWord.Spelling.cs` is split from `ModuleWord.cs`). Its own file `ModuleInterpretTrialTests.cs` drives `ModuleInterpret.Input()` headlessly.
- If the WPF app is running, building the solution fails copying `BrainSim Thought.exe` (file lock). Don't redirect `Tests` output elsewhere (`-p:OutDir=...`) to get around it: many tests locate fixtures relative to the repo and then fail spuriously. The headless `UKS.Tests` is unaffected.
- The user may have the solution open in Visual Studio; avoid `git stash`/checkout of files they have open (VS can save its stale buffer back over the restored file).
- `artifacts/` is gitignored build/experiment output (many copies of `UKSContent`); ignore it when searching.
- `UKSWeb/` (ASP.NET, built by the `Dockerfile`) and `iOS/`, `BrainSimMAC/` depend only on `UKS/`.

## Architecture

- **`UKS/`** — the Universal Knowledge Store library (`UKS.UKS`, partial class across `UKS.*.cs`). Everything is a `Thought`; a `Link` is a Thought with `From`/`LinkType`/`To`; a `SeqElement` is a Thought in an ordered sequence (`NXT`, `FRST`, `VLU` value links — an element may carry several VLU "facets", selected by class via `GetElementValue(element, valueClass)`). Inheritance is `is-a` (`Parents`/`Children`, `HasAncestor`, `HasProperty`). Each `UKS` instance is independent and there is no ambient store: a label is always resolved by a named store (`store.Labeled("dog")`, `thought.Store`, or a method taking a `ThoughtRef`, which converts implicitly from a Thought or a label). See `UKS/API.md` for the API plan. The core's public API is frozen: `UKS/PublicAPI.Shipped.txt` is checked at every build (RS0016/RS0017 are errors), so a new public member goes into `PublicAPI.Unshipped.txt` and a removed one leaves the list, deliberately; `UKS.Agents` and `UKS.Helpers` are exempt (`UKS.ApiFreeze.cs`). Thoughts are compared by identity, never by label (the core link types through internal lookups such as `IsAType`). Agents (`UKS.Agents`) and helpers (`UKS.Helpers`: `GetTargetOfFirstLinkOfType`, `AncestorsWithSelf`, `RemoveLinks`, `CreateThoughtFromMultipleAttributes`, ...) are extension methods in their own namespaces built only on the public API; a caller adds the `using`, and the core never calls them. The UKS knows no language: `CreateThoughtFromMultipleAttributes` takes an optional singularizer, which the hosts supply from Pluralize.NET. New stores: `new UKS(); store.CreateInitialStructure();` (`UKS.Initialize.cs` defines core types, `??` wildcard, `?`/`!`, sequence search options).
- **Dotted labels compose meaning** (`UKS.cs: GetOrAddThought`): `is.not.!` gets parents `is.not`, `!`; `??.noun` is a wildcard whose class is `noun`. `!` carries `setRelationship`, `?` carries `isPossible`. `UKS.ApplyTestOrSetAction(link)` (`UKS.Actions.cs`) strips those to the ordinary relationship type and either writes it (`.!`) or queries for matches (`.?`, wildcard operands search).
- **Text knowledge files** (`UKS.TextFile.cs`): one bracketed statement per line, `[from->type->to]`, nested `[a->means->[b->is.!->c]]`, sequences as `^a b c`, trailing number = weight, `#` comments. Loaded with `ImportTextFile` / `ProcessSingleLine`.
- **`BrainSimulator/`** — WPF host app. Modules (`Modules/Module*.cs` + `*Dlg.xaml`) derive from `ModuleBase` (WPF, `MainWindow`); `Initialize()`/`UKSInitializedNotification()` set up knowledge, the dialog calls module methods.

### ModuleInterpret — template-driven language understanding (experimental)

`BrainSimulator/Modules/Experimental/ModuleInterpret*.cs`, a partial class split by stage: `ModuleInterpret.cs` (fields, `Input`, `GetSequenceFromText`, inflected forms, `Execute`), `.Knowledge.cs` (`LoadLanguageKnowledge`, template definitions, saved-network migrations), `.Recognition.cs` (`GetTemplates`, `GetMeanings`, `Bind`), `.Generation.cs` (`GenerateSentence`), `.Reference.cs` (described noun phrases), `.Report.cs` (the diagnostic report text, kept out of `Interpret` so the pipeline reads stage by stage), `.Explanation.cs` (why/why-not answers), `.Pronouns.cs`. `UKS.Tests` links all of them by wildcard. Proof of concept: all grammar lives in the UKS as data; the code only matches and substitutes.

- **Words vs. concepts**: words are `w:dog` Thoughts (under `word` via a `wordType` class such as `noun`, `adjective`, `copula`, `possessionVerb`, `numberWord`), spelled by a character sequence (`spelled`), linked by `means` to a grounded concept (`dog`, or an action type like `chases.ongoing.!`, `has.!`). Vocabulary and demo facts: `BrainSimulator/UKSContent/BasicWords.txt` (loaded from `AppContext.BaseDirectory/UKSContent` — the file must be copied to the output dir). Word lookup is `ModuleWord.FindWordsBySpelling` / `RememberSpelling`.
- **Inflected forms**: meanings belong only to base words, singular and present tense (for verbs the third-person form, `w:chases`, `w:is`, `w:has`). A form (`w:dogs`, `w:are`, `w:have`) is under `wordForm` with only a spelling, linked from its base by a link type under `hasInflection` that `marksInflection` an inflection (`[w:dog->hasPlural->w:dogs]`, `[hasPlural->marksInflection->plural]`). Verb agreement is the verb's plural; `hasPastTense` (→ `pastTense`) and `hasPresentParticiple` (→ `presentParticiple`) cover tenses (`w:chased`, `w:ate`, `w:chasing`, `w:eating`). An inflection that `addsMeaning` modifies the base meaning when read (`FilledValue` → `WithInflection`, composing a dotted label: `chases.!` + past → `chases.past.!`); the plural adds none. A template element can require an inflection as an extra parent (`??.actionVerb.presentParticiple` in `verbPhrase1`); sequence search can't check that (wildcard parents are OR'ed), so `Fillers` (the recognition walk) does, and `ElementClasses` excludes inflections. Elements naming no inflection accept any. Every form is stored explicitly for now; spelling rules come later. In generation, a form counts as its base word's classes plus its inflection (so `precedesWord plural` admits `w:legs`, `presentParticiple followsWord copula` blocks "Dog chasing cat"); `WordsOf` offers base words before meaning-neutral forms, and `WordsExpressing` decomposes a modified concept (`chases.ongoing` = `chases` + what `presentParticiple` adds → `w:chasing`). `Fillers` also rejects a word whose inflection adds meaning in an element that is not a `means` operand ("Fido was a dog": the classification templates' copula supplies nothing, so the past would be lost). Not yet in place: comparatives, possessives; `w:fed`/`ongoingVerb` are leftovers no template uses.
- **Shared sentence sequences**: `AddSequence` returns an existing identical sequence, and inflected input collapses to the same base words ("Is/Was Fido black?"), so `GetSequenceFromText` clears `inflectedAs`, `matchesTemplate`, `fills` and phrase VLU facets from a reused sequence before marking it.
- **Questions**: a template with `hasProperty asksQuestion` takes its relationship type from its words and `AsQuery` turns it into a query (`is.!` → `is.?`, `is.past.!` → `is.past.?`); such templates are skipped by generation. The copula means `is.!`, and `copulaAttributeTemplate`/`attributeQueryTemplate` take their type from it, so tense reaches the meaning. "What do dogs do?" asks `action.?`, matching any type under `action` (BasicWords classifies chases, eats). Locations follow the UKSWeb labs' convention: `location` is a class of places (yard, doghouse, kitchen, inside, outside) and the relationship type is `located` (`w:in` means `located.!`; `locativeAdverb` words like `w:outside` name the place; "Where is Fido?" asks `located.?`). Other prepositions mean dotted subtypes (`w:under` → `located.under.!`), so `located.?` finds them. `location` is `isExclusive` and `recordsHistory`, so a new location archives the old one (below).
- **Prepositional phrases**: `locativeTemplate` (copula + PP), `nounPhrase4` ("the cat in the kitchen": a described referent, see Reference), `eventLocationTemplate`/`eventLocationAdverbTemplate` (an action placed: nested MEANS `[[subj->verb->obj]->located.!->place]`, Lab 4's form), `whereEventQueryTemplate`. Nested patterns go through `BindPattern` (recognition), `Execute`/`Resolved` (a nested write is stated first, or looked up in a question) and `Unify` (generation). `IsMeansOperand` looks at any depth. Generation skips a phrase containing its own class (`ContainsItsClass`), else `nounPhrase4` recurses forever. In a walk, nested phrases of one class are tried longest first (`Follows` walks NXT, no counting).
- **Reading rules**: a sentence template (direct child of `template`) must start at the first word (`GetTemplates`) and end at the last (`GetTemplates`); phrases can be anywhere. This settles PP attachment toward the reading that covers the sentence. Clauses: only when nothing covers the sentence (else "Rover are dogs" would be read inside "Fido and Rover are dogs"), `GetTemplates` makes a second pass in which a template under `clause` may also start right after, and end right before, a word that `joinsClauses` (BasicWords: `w:and`, `subordinator` `w:if`, `punctuation` `w:comma`); any other sentence template still spans the whole sentence. `Tokens` makes a comma a word of its own (its spelling is created in `LoadLanguageKnowledge`, a text file can't spell it). `clause` (a class of templates, listed in `LoadLanguageKnowledge`) holds the statement templates meaning one relationship, plus `compoundTemplate`; conjoined-subject templates, questions and rules are not clauses. A `??.clause` element takes the clause's statement (`UsableMeaning`: a clause child supplies its Link meaning, a phrase its non-Link one); a phrase fills only an element of its class, and a template the sentence runs out before doesn't match. `compoundTemplate` ("A and B") means `[A->conjoinedWith.!->B]`: both are stated (nested writes) and linked. A compound is itself a clause, so "A and B and C and D" is ((A and B) and C) and D, piled up by the `GetTemplates` loop (left nesting only: a template's first element can be an earlier match of itself; right nesting, "A and (B and C)" or "the cat in (the kitchen in the house)", isn't built). `conditionalTemplate` ("A if B") and `conditionFirstTemplate` ("If B, A", comma required) mean `[A->conditionalOn.!->B]` (not `IF.!`: in a definition IF's operands are parsed as patterns). Since a rule isn't a clause, "if" joins most loosely: in "A if B and C" the condition is "B and C". `Execute` writes a rule (`IsRule`, `WriteRules`, `RuleText`) as UKS text through `ProcessSingleLineWithNesting`: `[[fido->is->cold]->IF->[[fido->located->outside]->AND->...]]`, operands becoming `.?` patterns, nothing stated, conditionalOn → IF and conjoinedWith → AND; a compound result gives one rule per conjunct (the UKS evaluates single-relationship results). `GetAttributes` then answers from it once the conditions hold. Yes/no question templates are also `questionClause`s (a separate class, so "and" and a rule's result take statements only); `hypotheticalQueryTemplate` ("Is Fido green if Fido is outside?") means `[question->assuming.?->condition]`: `Execute` states the condition, then asks (the question's transaction is undone, so the assumption never stays); the answer says it with the assumption. Unknown words: a lone unknown word right after a joining word is guessed (as a bare noun) before clauses are looked for ("and Rover"), others after ("Fido is green and Fido is hungry": the clause reads "hungry" as an adjective). Only the winning match's own meanings are executed (`MeaningsOf(winner)`), so a clause reaches the UKS only through the sentence containing it; `Execute` lists nested facts it stated among its results. Teaching reads the pending sentence with `lookForClauses: false` (a clause facet would hide the phrases its units come from). In a question only the query meanings are executed; descriptive writes from its noun phrases are not.
- **History** (`UKS/UKS.History.cs`, moved unchanged from UKSWeb Lab 4): `AddStatementRecordingHistory` archives a displaced value (exclusive with the new one, and the type or target `recordsHistory`) as `was.TYPE` at the head of the source's `events` sequence (newest first, `validUntil` timestamps; repeat visits reuse the archived Relationship) and removes the conflicts. Called by `UKSWeb/StatementInputParser.Add` and by `ApplySetAction` (so every `.!` write). The desktop `ModuleUKSStatementDlg` "event" checkbox is a different thing: it logs the new statement itself into the same `events` sequence. `Execute` omits historical results from a present-tense question. Past tense in the interpreter is still `TYPE.past`, not the UKS's `was.TYPE`; reconciling them is deferred.
- **Templates**: Thoughts under `languagePattern` (`template` for wildcard patterns, `phrase` for fixed phrases like `p:is_a` in BasicWords). `hasWords` → a sequence of `??.class` wildcards and/or literal words; `means` → a wildcard (`??.noun`) or a Link pattern such as `[??.nounPhrase.subjectRole->is-a.!->??.nounPhrase.complementRole]`. All templates are text definitions in `LoadLanguageKnowledge()` (`quantityPossession0..9` in a loop over digits).
- **Roles, not positions** (a deliberate design constraint — no integer positions or counting in binding): a `means` operand refers to the template element whose value is the same Thought, so each wildcard/role may appear at most once per template. Where a class repeats, a role distinguishes the elements: `??.nounPhrase.subjectRole` has parents `??`, `nounPhrase`, `subjectRole`; roles (`subjectRole`, `complementRole` under `templateRole`) carry `isWildcard`, so only the class constrains fillers. A bare `??` operand that is not a template element is an open query variable. Don't name roles with plain English words or `object` (labels are case-insensitive and `Object` is a UKS root; typed words resolve to same-label concepts).
- **Pipeline** — `Input(sentence, rememberUnknownWords)` (the dialog passes `true`) returns a diagnostic text report. An input of several sentences (split on `.?!`) is interpreted one sentence at a time, each its own transaction; answers are joined. Per sentence:
  1. `GetSequenceFromText` — tokenize, lowercase, strip punctuation; resolve each spelling to a `w:` word; a stored inflected form is replaced by its base word and the sentence element gets `inflectedAs → plural` (no Pluralize.NET: the module must stay language-independent); unknown words throw `FormatException` unless remembered, in which case they get parent `unknownWordType`; ensure each word has a `means` concept; store as `SentenceIn*` (under `Sentence`) `hasWords` sequence.
  2. `GetTemplates` — every reading is kept (Option B of the ambiguity work, 2026-11-25; not the UKS sequence search any more): repeatedly, from each start word, every template is walked (`Walks`/`Fillers`): an element takes the word itself (literal, or class wildcard with its required inflection; an unknown word only into non-closed word classes; an inflection that adds meaning only in a `means` operand unless the word lends it) or any match already recorded there whose template is of its class, longest first. All ends are recorded, not just the longest; matches are only added, so the fixpoint doesn't depend on search order. Each match is a Thought of its own (`RecordMatch`, under `templateMatches`): its first word `startsMatch` it, it is `matchOf` its template and `endsAt` its last word. Covered words also get `matchesTemplate` links (report, tests, `IsCovered`). During recognition an unknown word may fill any non-closed word class; afterwards `ClassifyUnknownWords` gives it the classes it fills in the winning reading only (the strongest whole-sentence matches, all if tied; else the longest match at each word from the left), so "the hungry" doesn't make hungry a noun in "the hungry dog ate dinner". A lone unknown word already read inside a match is not guessed alone. Afterwards `PhraseFacets` gives each word one `languagePattern` VLU facet (longest match from the left) for teaching (`Units`) and display only. One match record per (template, start, end): different internal readings of the same extent share it (a known gap).
  3. `GetMeanings` — for each match record, take the first walk of its template (the same `Walks` as recognition, preferring the word, then longer inner matches) that ends exactly at its `endsAt` word, using only inner matches that already have a usable meaning (`UsableMeaning`: a clause its statement, a phrase its non-Link meaning or referent descriptor), recording `word -fills-> templateElement` links tagged `inMatch` → the match (an inner and outer match of one template fill the same elements); then `Bind` each `means` operand by reference (role → template element → words that fill it in this match → `FilledValue`: the word's inflected meaning, or the inner match covering those words) and attach results as `means` links on the match. `CoveringMatches` = matches at the first word ending at the last. Works from match records alone (a test builds one by hand). Iterates to a fixpoint.
  4. `Execute` — `ApplyTestOrSetAction` on each Link meaning: `.!` writes, `.?` queries ("Query results" section, then an "Answer" section).
- **Generation** — `GenerateSentence(Link fact)` runs a sentence template (direct child of `template`) in reverse: its `means` pattern unifies with the fact (element operands bind to the fact's Thoughts; fixed operands must express it, e.g. `is-a.!` expresses `is-a`), then its words are produced by walking the template. Bound elements → a word of the class whose `means` expresses the concept, or a phrase (child of the phrase class) whose own non-Link `means` is the bound element; unbound elements → a free choice of the class, never allowed for an element that appears in a `means` pattern. Each step lazily offers alternatives in preference order (base words before their inflected forms, then spelling order); the first word sequence satisfying the **word order constraints** wins. Those are BasicWords data, held by a word or inherited from its class: `precedesWord` (class of the next word that is not a modifier: `[adjective->hasProperty->isModifier]`, so `w:the` precedes the noun in "the black dog"), `precedesWordStartingWith` (class of next word's first letter, e.g. `w:an` → `vowel`), `followsWord` (previous word's class, e.g. `ongoingVerb` → `copula`). A phrase needing free choices is offered only when no phrase can express the concept without them (hence bare nouns via `nounPhrase3`, and "is an animal" rather than "is a the animal"). Only ordinary relationships are expressed (`.?`/`.!` types return null).
- **Articles and number in answers** — `GenerateSentence(fact, question)`: `NounsOf(question)` records each noun concept's article (or none) and plurality; `Express` then requires the same (hard) for those nouns, and for other nouns offers `nounPhrase2` with its article element bound to `a` first, then bare. The rest is BasicWords constraints: nouns are `countNoun`/`massNoun` (under `commonNoun`) or `properNoun`; `w:a`/`w:an` precede only a singular `countNoun`, `w:the` a `commonNoun`, `numberWord` a noun. `numberWord` is its own `wordType`, not an adjective (else "3 legs" reads as a described noun phrase and the quantity templates never match). `WordClasses` gives a base word the class `singular`. `AgreesInNumber` (in `FollowsWordOrder`): every word whose class has `agreesInNumber` (`verb`) is plural exactly when the sentence's first noun is, if it has a plural form and isn't a tense form. Without a question, answers default to singular with "a" ("A dog has a tail."). Learned nouns are plain `noun`, so they never get "a".
- **Transactions and undo** — `UKS/UKS.Journal.cs`: transactions (internal `BeginTransaction`/`EndTransaction`/`Undo`; public `ChangeUndoably`, `TryChange`, `UndoLast`, `CreatedInCurrentChange`) record structural changes (Links added/removed via `Thought.AddLink`, `UKS.WriteTheLink`, `Thought.RemoveLink`; Thoughts created when first labeled, in the `Label` setter) and reverse them newest first. Also recorded: relabels (`ThoughtRelabeled`, old label) and `Thought.Delete` of a non-Link (`ThoughtDeleted`; undo re-registers label and `AtomicThoughts`, then its removed Links come back). Weights, firing and TTL are not recorded. Transactions don't nest. One undo history per store: `ChangeUndoably(description, action)` and `TryChange(description, func)` (kept only if it returns true) push, `UndoLast` pops whichever source made the change — the Undo buttons in the Interpret, Add Statement and UKS dialogs (delete, delete child, delete link, rename) all share it; UKS-dialog Import is not undoable. `Input` runs as one `TryChange`: undone unless the sentence is understood (`IsUnderstood`: one template with a meaning covers first word to last) and is a statement that executed something, so questions and misunderstood sentences leave the UKS unchanged and teach no words. Kept statements go on a stack for `UndoLastInput` (dialog: "Undo last statement").
- **Teaching** (`ModuleInterpret.Teaching.cs`) — a not-understood sentence sets `pendingSentence` and the reply asks to have it said another way. `Input` offers the next input to `TryToLearnFromExplanation` (not if it is the same words repunctuated: that's a correction, read as new): it is an explanation only if every sentence in it (split on `.?!`) is an understood statement and it shares a meaning with the pending sentence; otherwise it's undone and read normally. `Units` splits the pending sentence into recognized phrases and words with their meanings; `Align` maps each source/target Thought of the explanation's statements to exactly one unit (types map if a unit means them, else stay fixed); unmentioned units must be closed-class words (kept literal), else a specific "doesn't mention" reply. `DefineLearnedTemplate` writes text definitions (`learnedTemplate*`, roles `learnedRole*` under `templateRole`), one MEANS per statement plus `[[a]->conjoinedWith.!->[b]]` between consecutive statements (`conjoinedWith` isCommutative), marks it `isLearned` and `Capture`s it (Learning, below). The whole teaching exchange is one undoable transaction. Undo also clears `SequenceCache` entries for sequences it removes.
- **Learning** (`ModuleInterpret.Learning.cs`, deliberately domain-free so it can move into the UKS) — the user's model is match / capture / compete / consolidate / prune; prune is not implemented. A pattern's strength is the template Thought's own `Weight` (hand-written templates 1). `Capture`: weight 0.25, `IsPlastic`. Compete: `CoveringMatches` orders whole-sentence readings by `Preferred` (below) and `Covering` is the winner; `LosingMeanings` drops the rivals' meanings (unless the winner means the same) before `Execute`; equal-length phrase matches in `GetTemplates` are ordered by weight (`ByWeight`) for the phrase facet. Only the winner's outcome counts: losing costs nothing, and matching alone is not evidence. Success (a statement stored something, a question found an answer) → `Strengthen` (halfway to 1; past 0.8 `IsPlastic` is cleared, but the weight can still change later) and each stated fact gets `statedBy` → the template (provenance, for later evidence-based forgetting). "(I'm still learning sentences like this one.)" while the winner was plastic. Fact weights are confidence only. Weight changes are not journaled, so Undo doesn't revert them. Lessons from `ModuleSequenceSegmenter` (why it isn't reused): an early false pattern could never be removed (consolidation was absolute and full recognition blocked rivals), learning needed repeated occurrences, and decay per miss made survival depend on input-suite size — so: capture on one presentation, never treat consolidation as permanent, and count failures only where the pattern was relevant. Two templates with identical words share one `hasWords` sequence and both match.
- **Misspellings** (`ModuleInterpret.Spelling.cs`) — in `GetSequenceFromText`, a spelling with no exact match goes to `CorrectedSpelling` before being learned: `ModuleWord.FindWordsCloseTo` runs the UKS `ApproximateSequenceSearch` (options `allowOutOfOrder`, `preferFirstLast`, `allowPartialMatch`; `UKS/UKS.SequenceApproximate.cs` `FindSequencesOutOfOrder`, dispatched from `FindSequencesByActivation`). Letters activate stored elements in any order, propagating up through compressed subsequences; confidence = activated share of the longer × (0.9 + 0.1 × in-order neighbor pairs) × 0.8 per wrong first/last letter. One candidate ≥ 0.85 is read silently with a note ("(I read "fdio" as "fido".)"); a best candidate ≥ 0.65 throws `UncertainSpellingException` → "Did you mean "the"?" with nothing learned; a lone `w:yes`/`w:no` (`replyWord`, meaning `affirmative`/`negative`) answers and rereads the sentence; anything else is new input. Answers are remembered for the session only (`acceptedCorrections`, `notMisspelled`).
- **Reference** (`ModuleInterpret.Reference.cs`) — a template that `hasProperty describesReferent` (`nounPhrase1` article adjective noun, `nounPhrase5` adjective noun, `nounPhrase4` with a PP) means the thing its description picks out, never facts about its class. `GetMeanings` (`DescribedReferent`) replaces its head and description meanings with one descriptor Link `[head->oneDescribedAs|kindDescribedAs->[head->is.!->black]]` (a nested phrase's descriptor can be the head); `UsableMeaning` passes descriptors up like non-Link meanings. One vs kind is decided by the words: a first word that `isDefinite` (`w:the`, BasicWords) and a head with no plural filler → one; otherwise ("a black dog", "black dogs") a kind. Nothing is searched or made during recognition (losing readings leave no trace); `Execute`/`Resolved` call `Referent` for the winner. If the class itself satisfies the description (via `GetAttributes`), the class is the referent (nothing told apart). One: descendants that are not classes or `isAnonymousClass`, named or not (Fido) and satisfying it; several → `UnclearReferentException` ("I can't tell which dog you mean: fido or rover."); none → a new child `dog0` with `isInstance` and the description (a question gets no answer instead). Kind: an `isAnonymousClass` child with the description, found or made. Exception: an is-a write to a kind ("Rover is a small dog", `IsJoiningAKind`/`JoinKind`) makes no subclass: Rover is-a dog and is small (an agent like `ModuleClassCreate` may later make the class); this replaced `classificationAttributeTemplate`s (deleted from saved networks). An input that is only a describing phrase ("The hungry dog") introduces/finds its referent (`Introduced`). Generation (`ExpressReferent`) says a made referent (no word, `isInstance`/`isAnonymousClass`) with a describing phrase, article phrases first: "the" for an instance, "a" for a kind; the description is its first fact a phrase can say. Context that would settle which of several is meant is not considered.
- **Relationship explanations** — An input written as relationships (`IsRelationshipText`: starts with `[` or contains `->`/`→`) is taken as relationships (`[cat->chases.past->fido] [cat->chases.past->rover]`, nesting and `→` allowed) explaining the pending sentence, in place of sentences: `ParseRelationships` (Teaching.cs) builds unwritten Links (a type gets `.!` unless it has `.!`/`.?`; unknown labels are made, inside the teaching transaction) and they go through the same `Align`/`DefineLearnedTemplate`. A parse problem or no pending sentence gets a specific reply; the sentence keeps waiting.
- **Explanations** (`ModuleInterpret.Explanation.cs`) — after a yes/no query (no wildcard), `RecordEvidence` reads `UKS.Why()`/`WhyNot()` at once (any later `GetAttributes` resets them) and keeps, for each stored rule whose result is what was asked (`RulesFor`: a `TYPE.?` possibility on the subject with an IF), its condition leaves (through AND), which held, and for each failed one a `Contradiction` (an attribute `LinksAreExclusive` with it, e.g. inside vs outside, or `TYPE.not`). Answers: "Fido is wet, because Fido is outside." / "I don't know. Fido is wet if Fido is outside, but Fido is inside." / "..., but I don't know whether Fido is outside." A question no rule bears on is still plain "I don't know." (no "probably not"). The English frames are constants there, to become templates later. `GenerateClause` gives a fact without capital/period; `Format` capitalizes proper nouns anywhere.
- **Pronouns** (`ModuleInterpret.Pronouns.cs`) — `w:he/she/it/him/her` (`pronoun` under `noun`, closed class) mean the stand-in `pronounAntecedent`; `WithAntecedents` replaces it in the winner's meanings before acting: the first subject of the sentence (`Subjects` follows sources outermost first; a described referent counts as one), else `lastSubject` (what the previous understood sentence was about), else a FormatException reply. Gender and number are not checked; no "they".
- **Motion and auxiliaries** — `w:goes` (`motionVerb`, `goes` under `action`) with `go`/`went`/`going`/`gone`; `motionTemplate` ("Fido went outside": `[fido->goes.past.!->outside]`, a clause), `whereMotionQueryTemplate` ("Where did Fido go?"), `wherePerfectMotionQueryTemplate` ("Where has Fido gone?"), and yes/no `motionQueryTemplate`/`perfectMotionQueryTemplate`. An auxiliary class that `hasProperty lendsInflection` (`doAuxiliary`; `w:did` is the past of `w:does`) passes its inflection to the plain-form verb of the same match (`Bind` → `LentInflection`; `Fillers` lets such a word's inflection go unused itself), so "did go" = goes.past and "Did Fido chase the cat?" asks chases.past. The copula doesn't lend. `pastParticiple` (`hasPastParticiple`, `w:gone`) adds `past`: the perfect is read as the past; `w:has` is also a `perfectAuxiliary`; `[pastParticiple->followsWord->perfectAuxiliary]` keeps generation saying "went". A wildcard query finds tensed subtypes, so "Where does Fido go?" also lists past goings. Going somewhere doesn't yet imply being located there; no "to the yard" yet.
- **Conjoined subjects** — `conjoinedClassificationTemplate`/`conjoinedAttributeTemplate` ("Fido and Rover are dogs."): `secondSubjectRole`, one MEANS per subject; `w:and` is a closed-class `conjunction`.
- **Report** — "Word attachments" lists each sentence word with its classes, properties and inflection, then its templates: `w:is (copula, pastTense)    attributeQueryTemplate`.
- **Dialog** — Enter in the input runs `Input`; the Answer box shows `ModuleInterpret.Answer` (query answer, "I don't know.", "OK.", "I don't understand.", or the unknown-words message) and Details shows the diagnostic report.
- Queries go through `GetAttributes` (`ApplyTestAction`), so they inherit and see rules whose conditions are met. A yes/no query (no wildcard) needs exactly the type asked (`is.past` doesn't answer `is`); `is-a` isn't among attributes, so it uses the stored link.
- **Ambiguity experiment (A)**: `ModuleInterpret.ExtraVocabularyFiles` (static, normally empty) are imported after BasicWords. With env var `INTERPRET_AMBIGUITY=1`, `UKS.Tests/InterpretAmbiguityExperiment.cs` (a module initializer) adds the first section of `WordNetWords.txt` — the classes WordNet gives BasicWords' own words (w:dog verb, w:brown noun/verb, w:in noun/adverb; 41 links) — to every ModuleInterpret in the run. Results (2026-11-25): with the old greedy recognizer (one phrase facet per word, chosen in search order) 53 of 239 ModuleInterpret tests failed: a wrong local reading (w:in as `nounPhrase3`) hid the word's other classes. With every reading kept (step 2 above) the normal suite passes (and runs faster, ~16 s) and 43 fail with ambiguity: locations and prepositional phrases now read correctly; the failures are ties between whole-sentence readings at equal weight ("Fido is green": copulaClassificationTemplate vs copulaAttributeTemplate; the first recorded wins), readings inside a clause sharing one match record, and generation ("Fido is animal"). Experiment B (2026-11-26) chooses by grammar and knowledge, both as data: (1) a singular common noun needs a determiner (BasicWords `[commonNoun->hasProperty->needsDeterminer]`, `[massNoun->hasProperty->standsBare]`); templates that `lacksDeterminer` (`nounPhrase3`, `nounPhrase5`, `bareClassificationQueryTemplate`) take only a plural or bare-standing noun (`MayStandBare`, in `Fillers` and generation's `ExpressTemplate`), so "Fido is green" is no longer "Fido is a green" and generation no longer says "is animal"; a template whose fixed words supply the determiner takes `??.noun` directly (`classificationTemplate` after "is a", `quantityPossession*` after the digit). (2) A relationship type can name what its target is (`[located->expectsTarget->location]`); `Fit` scores a reading's meanings (+1 met, -1 contradicted, nested too). (3) `Preferred` (Fit, then weight, else stable) orders readings of the same words everywhere: `CoveringMatches`, inner readings in `Fillers` (after longest first) and `FilledValue`, so a clause inside "A if B" takes its best reading. `ClassifyUnknownWords` still uses weight only (it runs before meanings exist). Generation: a word that can also be a modifier (w:animal, adjective in WordNet) may itself be the head `precedesWord` is about (`Heads`); one head must meet all of a word's rules. With ambiguity on, 1 of 239 fails (a report line lists w:dog's extra class `verb`). Same-meaning ties remain and are harmless. Next idea (user): templates as phrases with wildcards, organized specific-under-general, so specificity ranks readings.
- `InterpretLanguage.txt` is an older `interpret:`/`slot:` dialect and is **not loaded** (import commented out). `InterpretTrials.txt` lists the demo sentences and expected relationships; they are automated in `UKS.Tests` (`ModuleInterpretTrialTests`) and `Tests/ModuleInterpretTests.cs`.
- Output strings use `→` (e.g. `[fido→is-a.!→dog]`); tests assert on these.

### ModuleInflect — inflection by rule (experimental, standalone)

`BrainSimulator/Modules/Experimental/ModuleInflect.cs` (+ `ModuleInflectDlg`: type a word, Enter shows everything known about it; `Report`). Not yet used by ModuleInterpret. Loads `BasicWords.txt` then `UKSContent/Inflections.txt` (copied to output; linked into `UKS.Tests`, tests in `UKS.Tests/ModuleInflectTests.cs`).

- Intent: a regular word is stored once in its base form (noun singular, verb bare stem, adjective plain); regular forms come from rules, only exceptions are stored (`[w:goes->hasPastTense->w:went]`), and a stored form blocks every rule. Closed-class words take stored forms only.
- An inflection says which class it `inflects` (`plural`→noun, `thirdPersonSingular`/`pastTense`/`pastParticiple`/`presentParticiple`→verb, `comparative`/`superlative`→adjective); a class can `lacksInflection` (massNoun, properNoun, pronoun → plural). `hasThirdPersonSingular`, `hasComparative`, `hasSuperlative` are the exception link types.
- A rule `formsInflection` one or more inflections and replaces the end of the base spelling (`baseEnding`, a letter sequence; absent = nothing) with `formEnding`. Letter-class wildcards (`??.consonant`, `??.sibilant`, `??.doublingConsonant`, `??.silentEConsonant`) bind by reference across the two endings; `letterRole1..3` (wildcard roles) tell repeated classes apart (doubling repeats `letterRole3` in the form).
- Rules are an is-a tree: each default rule (`sDefault`, `edDefault`, ...) is a direct child of `inflectionRule`; a child rule is an exception to its parent. What a rule forms and its backward preference come from UKS inheritance (`GetAttributes` on the rule only, cached in `RuleAttributes`, cleared on reload; never on words): a child inherits its parent's `formsInflection` (`[sAfterO->formsInflection.not->plural]` overrides one), and `readsBackward` → `preferred`/`avoided` (under exclusive `backwardPreference`; `inflectionRule` is preferred) is overridden by a child's own. Endings are the rule's own links, not inherited.
- Forward (`ApplyRules` → `MostSpecificRule`): descend from the top to the deepest rule whose base ending matches (siblings both matching: the longer ending, `IsLonger`). Backward (`Analyze`): every rule whose form ending the spelling has gives a candidate stem; a candidate counts only if a base word has that stem and the forward `Forms` gives the spelling back (so "goed" is rejected: `Blocked` reports go has went), credited to the forward rule. Unknown words (`Guesses`): candidates that survive the same forward check, preferred rule before avoided, then a rule before its ancestors (washes → wash; horses → horse via avoided `sAfterS`, kisses → kiss via preferred `sAfterSS`; walked → walk via avoided `edAfterE`, smiled → smile via preferred `edAfterVowelConsonantE`; taller → tall via avoided `erDoublingFloss`, the "floss" rule for f/l/s/z). The forward check also settles many cases outright: liked can't be lik, which would give likked (`doublingConsonant` is every consonant but c, h, j, q, w, x, y). Preferences affect only unknown words. About 1 ms per word for Analyze + Guesses.
- Derivations: a `derivation` is an inflection that `derives` a word of another class; it's applied to the class it `inflects` and spelled by rules like any inflection. `adverbial` (adjective → `mannerAdverb`, under new `adverb` wordType; exception link `hasAdverbial`), rules `lyDefault` and children (happily, gently via preferred `lyAfterStopLE` under avoided `lyAfterConsonantLE`, truly, fully, basically). The report shows "→ mannerAdverb" (`Derived`). A drifted word (hardly) is stored as its own word with its own `means`, and its base stores its real adverb (hard), which blocks the rule's reading. Guess ranking between unrelated rules: the longer form ending (basically: basic, not basicall). Not yet in ModuleInterpret (planned: a manner template, `[[subj->verb->]->manner.!->quick]`). Color adjectives should lack `adverbial` but have no class of their own yet.
- Knowledge files are imported once per store: `LoadInflectionKnowledge` runs both from `UKSInitializedNotification` and the first `Fire` (`Initialize`), and skips a file whose marker (`loaded_WordNetWords`, under `loadedKnowledgeFile`) exists; the marker is saved with the network, so a saved network reloads in seconds without the 80 s text import. To bring an edited file into a saved network, delete its marker.
- WordNet vocabulary: `KnowledgeFiles` (default `BasicWords.txt`, `Inflections.txt`, `WordNetWords.txt`; `CoreFiles` without WordNet, which the fast tests use). `WordNetWords.txt` is generated by `UKSContent/make_wordnet_words.py` from WordNet 3.1 (its license must stay in the header): lemmas in WordNet's sense-tagged corpus (~18.8k; `--all` gives 85k but loading takes ~20 min, since each new spelling's identical-sequence search in `AddSequence` grows with the store), one entry per spelling with a parent per class (`w:good` is-a `commonNoun`, `adjective`, `adverb`; 16,690 words, 18,795 class links), spellings BasicWords has are skipped, no meanings. A form is labeled by its spelling, so one spelling is one word: `w:better` is an adjective, verb, noun and adverb and also (is-a `wordForm`) the stored comparative of good and of well; `Analyze` reads it every way (`BasesOf` gives all bases of a form, `IsBaseWord` = has a class besides `wordForm`). `InflectionsOf` takes each class separately, so one class lacking an inflection (properNoun) doesn't stop another class of the same word. Irregular forms come from the `.exc` lists where the inflection is clear from the spelling; past vs past participle isn't, so swam/swum are missing. The `.exc` lists include variant plurals (busses, dwarfs/dwarves), which as stored forms block the regular one (buses). Load ~86 s, lookups ~27 ms per word. `ModuleInflectWordNetExperiment` (slow) prints what common forms are read as.
- Suffix-only for now (the stem is implicit: everything before the ending). Known misfires: doubling on multisyllables (visit → visitted, "glorped" → glorpedded) since stress isn't in the spelling.
- Transitional: BasicWords still stores verbs under the third person (`w:chases`, stem `w:chase` as its plural form), so a verb's stem is its stored plural form and its third person singular is the entry itself (`StemSpelling`, `Forms`). Switching BasicWords to bare stems (and ModuleInterpret to the rules) is the next step.
